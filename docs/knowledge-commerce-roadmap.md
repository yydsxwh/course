# 知识付费升级剩余项

本文记录 `course` 仓库在优惠券 0 元购修复之后，仍未实现的能力。这些项没有用占位按钮冒充完成。

## 已完成（Wave 0）

- 旧待支付订单不再吞掉后来选择的满额券。未向支付机构下单时，旧订单取消并释放优惠券，按新价格重建。
- 应付 0 元的订单直接记为已支付，核销优惠券并发放学习权限，不调用微信或支付宝。
- 已经生成支付二维码、支付链接或第三方交易号的订单返回 409，前端提供继续支付和取消入口；取消不会静默作废支付中的订单。
- 历史 `PENDING + amount=0` 订单在结账页和支付接口幂等履约。
- `npm test` 会执行 `create-order.test.ts` 与 `coupon-campaign.test.ts`。
- `scripts/resume_deploy.py` 不再包含硬编码密钥，并且默认拒绝执行。
- `scripts/deploy_safe_update.py` 用部署前后动态快照核对用户、订单、活动和券实例，不再要求恰好 1400 张券。

## 未做：P1

依赖：先观察 0 元购线上是否稳定，再逐项独立提交。不要和交易修复混在同一个无法回滚的提交里。

- 站长经营工作台 2.0：按 `Asia/Shanghai` 的今日、昨日、近 7 天、近 30 天和自定义区间聚合新增用户、付费用户、订单、成交额、优惠额、退款额、净收入、客单价和支付转化率。数字必须在服务端聚合。尚未有真实订单来源的 VIP、讲师销售额不要填假数。
- VIP：方案、权益范围、会员订单复用现有支付履约、到期失效、主动续费、站长赠送/冻结和审计。不做自动代扣。会员失效不能删掉用户已经买断的课程权限。
- 短链与渠道归因：不可枚举 slug、只跳转本站或白名单、访问/注册/支付漏斗、订单保存归因快照。渠道归因和佣金推荐人分开存。
- 用户 CRM：在现有用户管理上增加标签、消费和学习档案、按角色收窄可见范围，导出默认脱敏。
- 课程售卖设置：划线价、会员价、开售停售、学习有效期、发布检查、批量上下架/改价/分类/复制。保留旧 URL。
- 订单与售后：分页和筛选、用户取消未支付订单（已有基础）、退款状态模型。只有接上微信/支付宝退款 API、幂等键和回调校验后，才允许把订单标成已退款。

## 风险

- `scripts/resume_deploy.py` 历史上写过生产认证密钥。站长应轮换 `AUTH_SECRET`。轮换后已登录用户需要重新登录。不要为了抹掉历史密钥去改写 Git 历史。
- 生产库仍是 SQLite。P1 的统计和 CRM 要分页，不能把全量订单拉到浏览器。
- 课程产品代码留在本仓库。账号、支付、短信、对象存储继续用现有 shared/platform 适配，不在这里再造一套。
